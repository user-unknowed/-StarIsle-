01背景与目标

本产品不是聊天应用，而是一个 Agent 运行时的控制台：它面向"运行一个本地 AI Agent"这件事本身，把通常散落在命令行参数、环境变量与日志文件里的运行时状态，变成可看、可配、可治理的界面。

证据 —— 两份逆向报告共同刻画了一个 AI Agent 运行时的完整形态：桌面报告 §1/§5 Electron 外壳 + Cordis 内核加载 273 个 @deepseek-ai/dsh-* 插件，捆绑 Node / Python / pnpm 本地执行环境；桌面报告 §6.5 沙箱默认 read-only，写文件需切模式或批准；桌面报告 §6.6 凭据只存环境变量引用、不存明文值；网页报告 §5.3 会话是树状结构（parent_message_id），补全请求携带 thinking_enabled / search_enabled；网页报告 §5.1 模型目录由服务端下发、客户端零硬编码。

受影响的用户与时刻 —— 开发者 / 评测者在配置与观察一次 Agent 会话时，需要同时面对命令行开关、env 变量、审批弹窗与会话日志文件，状态分散且不可见。

产品决策 —— 做一个 Web 形态的运行时控制台 Harness Console，把运行时的"配置—运行—观察—治理"四类动作收进同一个界面，并把这个运行时的设计初衷显性化：本地优先、安全默认、插件化、可观测。

期望的可观察结果 —— 一名用户从打开页面开始，能在不查阅任何文档的情况下走完"创建会话 → 配置参数 → 发起运行 → 观察流式输出与工具调用 → 处理审批 → 查看会话树分支"；并且界面上随时可见三类安全表达：沙箱默认只读、凭据永不显示明文、危险模式必须二次确认。

02用户与产品契约

要素定义
主用户AI Agent 工具的开发者与评测者：熟悉命令行与 JSON 配置，需要一个统一的可视化面来配置、运行、观察一个 Harness 风格的 Agent 运行时。
触发打开 Harness Console（浏览器 / 离线打开原型）。
核心任务完成一次受控的 Agent 会话：从创建、配置、运行，到观察输出、处理审批、回看分支。
完成条件上述核心任务在界面内闭环走通，无死路；每一步的运行时状态变化都在界面上有可见反馈。
信任底线三条产品红线：① 凭据永不显示明文（掩码 + 只展示引用名）；② 沙箱默认 read-only；③ danger-full-access 必须经过后果确认。桌面报告 §8
数据边界原型阶段全部数据为本地 mock；界面上不出现"连接真实模型/API"的行为承诺。

04对象与状态模型

4.1 核心对象

对象关键字段说明与出处
会话 Sessionid、createdAt、cwd、isSeeded、delegationDepth、version(v4)会话头部字段沿用持久化格式定义；cwd 是沙箱工作区根。桌面报告 §6.4
消息 Messageid、parentId、role、blocks[]（思考 / 正文 / 工具调用 / 引用）以 parentId 构成树；"重新生成"产生新分支。网页报告 §5.3
模型 Modelmodel_type、name、enabled、switchable、show_model_name_in_session、contextWindow、modalities、maxOutput目录字段沿用服务端热控配置结构；具体取值见 §5.1。网页报告 §5.1 桌面报告 §6.1
沙箱策略 SandboxPolicymode ∈ read-only / workspace-write / danger-full-access、workspaceRoot、policyText桌面报告 §6.5
审批请求 Approvalid、tool、target、summary、status由工具调用触发，结果回流会话。桌面报告 §6.5（解析优先级）
凭据 CredentialRef：环境变量名 + 解析层级；Key：<scope>/<id> + 掩码值双空间：引用（Ref）与记录（Key）。桌面报告 §6.6
插件 Pluginpackage、group、enabled、role273 个 dsh-* 插件、10 个子系统分组。桌面报告 §5

4.2 关键状态机

会话运行状态：idle → running → (awaiting_approval → running) → completed | failed。运行中禁止再次发送；awaiting_approval 时消息流顶部出现阻塞条，审批完成后自动继续。

审批状态：pending → approved | rejected；rejected 后该工具调用在消息流中以失败块呈现，可重新发起。

沙箱模式：三值互斥；解析优先级为 显式批准的模式 > 会话级覆盖 > 部署默认（read-only）；切换以 sandbox/mode 事件追加到会话，重启后靠回放重建。桌面报告 §6.5

05功能需求

5.1 FR-1 · 会话控制台 P0

目的：在单一界面完成 Agent 会话"创建 → 配置 → 运行 → 观察 → 分支"的闭环。布局：左侧会话列表；中部消息流（树状）；底部输入区（composer），其上为运行参数条。

ID能力触发 → 处理 → 结果规则与出处
FR-1.1新建会话点击"新建会话" → 生成会话头（id、createdAt、cwd 默认 ~/projects/demo）→ 列表置顶新增项并进入空会话态（欢迎文案 + 示例提示词）cwd 即沙箱工作区根；桌面报告 §6.4
FR-1.2运行参数配置composer 上方参数条：模型选择、思考开关、搜索开关、推理强度、输出详略 → 修改即生效于下一次发送，并记录一次 selected_model_switch 风格的切换原因字段定义见 FR-1.3；网页报告 §5.2/§5.1
FR-1.3参数字段模型：deepseek-flash（默认，1M 上下文，text+image）、deepseek-v4-pro（1M 上下文，text）；推理强度：off / low / high / max，默认 high；输出详略：high / low；思考、搜索开关默认关；默认最大输出 256,000 tokens（展示于参数提示）桌面报告 §6.1
FR-1.4PoW 前置点击发送 → 先展示三步进度（获取挑战 → 本地求解 → 提交）→ 完成后才开始流式回复；失败可重试网页报告 §6.1；进度时长为演示值 Assumption, TBD
FR-1.5流式回复渲染mock 流式：思考块（仅思考开启时，可折叠，灰色斜体）→ 工具调用块（如触发）→ 正文逐字输出；消息含模型名（受 show_model_name_in_session 控制）桌面报告 §6.1 网页报告 §5.1
FR-1.6工具调用块bash / fs / web_search 三类；块内展示命令或目标路径、执行状态；web_search 附结果卡片（url / title / page_age）与引用摘要（cited_text），按 URL 去重桌面报告 §6.2
FR-1.7写操作与审批联动写请求先经沙箱裁决：workspace-write 且目标在工作区根内 → 直接执行；目标在工作区外 → 进入审批队列，消息流顶部出现阻塞条（跳转沙箱页处理）；read-only → 直接拒绝并说明原因（不经审批，见 FR-2.4）；拒绝后该块显示失败并说明解析优先级见 §4.2；桌面报告 §6.5
FR-1.8会话树与分支对任一 assistant 消息"重新生成" → 以其父消息为新分支起点，树状视图中并排展示分支，可点击切换当前分支；非当前分支内容折叠显示网页报告 §5.3
FR-1.9会话管理会话列表：置顶最新活动、显示消息数与当前沙箱模式徽标；支持重命名；空列表展示空状态引导—

状态与例外：流式中断（mock 超时场景）时消息尾部出现"空闲超时，可重试 / 新消息后继续"的操作条（对应 300,000 ms 空闲超时规则 R1）；运行中发送按钮禁用；PoW 失败提示重试；空会话有引导，不出现空白屏。

5.2 FR-2 · 沙箱与审批 P0

目的：把"安全默认"变成看得见的治理面。布局：三张模式卡片 + 审批队列 + 策略文本预览 + 工作区根信息。

ID能力触发 → 处理 → 结果规则与出处
FR-2.1模式查看与切换三张卡片呈现当前模式（高亮）与两种备选；点击切换 → 写入会话级 sandbox/mode 覆盖事件 → 徽标全局更新（含会话页）桌面报告 §6.5
FR-2.2危险模式确认选择 danger-full-access → 弹出二次确认：后果清单（任意文件可写、无审批拦截）→ 需勾选"我理解后果"后确认；取消则回退原模式信任底线③；桌面报告 §8
FR-2.3风险对比可视化卡片内以三档色（安全 / 受限 / 危险）与说明文案对比三模式的文件写权限、审批行为、适用场景—
FR-2.4审批队列列表展示 pending 请求（工具、目标路径、内容摘要、所属会话）→ 批准 / 拒绝 → 状态变更并回流到会话消息流；read-only 模式下的写请求自动拒绝并附原因桌面报告 §6.5
FR-2.5策略文本预览展示随模式变化的 sandbox:policy 注入文本，标注"该文本会注入系统提示上下文"桌面报告 §6.5

状态与例外：审批长时间未处理保持 pending 且在导航上计数提醒；会话运行中切换模式即时生效但对进行中的运行需重发后体现；无 pending 时队列显示空状态。

06共享规则与例外

R1流式空闲超时：流式回复空闲超过 300,000 ms 判定超时，界面给出"重试 / 继续"操作；原型的演示超时为可触发的 mock 场景。桌面报告 §6.1
R2PoW 前置：任何一次补全请求前必须完成 PoW（获取挑战 → 本地求解 → 提交），失败不发送请求并允许重试。网页报告 §6.1
R3审批事件回流：审批的批准 / 拒绝结果以事件形式回流到所属会话的消息流与事件记录，两处状态保持一致。桌面报告 §6.5
R4模型热控表达：模型目录视为"服务端下发"；enabled=false 的模型在选择器中禁选并注明"已下线"，switchable=false 时不可切换。网页报告 §5.1
R5遥测可禁用：遥测开关关闭时不产生任何上报行为；此规则在总览页可见、可操作。网页报告 §6.4
R6mock 边界：所有数据来自本地 mock 与桩 API；任何页面不得出现真实网络请求。接入点以桩函数形态预留，便于后续替换。

07术语表

Harness / 运行时
承载 Agent 循环的本地运行环境：插件内核 + 工具执行（Node / Python）+ 会话持久化 + 沙箱。
Cordis 插件
运行时的能力单元；本产品语境下"插件"特指 dsh-* 插件包，如 dsh-llm-deepseek。
PoW（Proof of Work）
补全请求前的工作量证明挑战，客户端本地求解后随请求提交。
会话树 / 分支
消息以父子关系构成树；对历史消息重新生成会创建新分支，分支间可切换。
思考模式 / 推理强度
思考开关控制是否输出思考块；推理强度（off/low/high/max）控制思考深度。
verbosity
输出详略档位（high / low），影响重新生成时的输出风格。
沙箱三模式
read-only（默认，禁写）/ workspace-write（仅工作区内可写）/ danger-full-access（不限写）。
CredentialRef / CredentialKey
凭据的两种形态：环境变量引用（只存名）、作用域记录（<scope>/<id>）；两者都不展示明文值。
DSH Home
运行时家目录（默认 ~/.dsh），存放会话、缓存与本地索引。
JSONL / zstd
会话持久化格式：每行一个事件；支持 Zstandard 压缩。
