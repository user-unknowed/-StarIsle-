## 4. 部署方案

### 4.1 前置：恢复本地 APK 产物

当前工作区 `docs/promo/` 缺少 `downloads/`（仅存在于 `main` 历史中）。执行前从 `dist/` 复制：

```
docs/promo/downloads/StarIsle-teacher-release.apk   (12.84 MB, 2026-11-20)
docs/promo/downloads/StarIsle-student-release.apk   (12.65 MB, 2026-11-17)
docs/promo/downloads/StarIsle-parent-release.apk    (12.54 MB, 2026-11-17)
```

### 4.2 GitHub Pages（主通道）

1. `git worktree add .tmp-wt-main origin/main`（临时目录加入 `.git/info/exclude`）。
2. 将改好的 `index.html` 与 `downloads/*.apk` 复制进 worktree。
3. `git add docs/promo` + `git add -f docs/promo/downloads`（`*.apk` 被 `.gitignore` 忽略），提交信息：`feat(promo): 按真实训练与验收结果更新宣传文案（v2.3）`。
4. `git push origin HEAD:main`（禁止 force-push）。
5. 轮询 Actions：`/repos/user-unknowed/-StarIsle-/actions/runs?branch=main`，等待 `Deploy Promo Page` 达到 `success`。
6. 清理 worktree。

### 4.3 Cloudflare Pages（新增通道）

目标：把 `docs/promo` 完整产物（`index.html` + `.nojekyll` + 3 个 APK，约 40 MiB）发布到已存在的 `starisle-promo` 项目，恢复并更新 `https://starisle-promo.pages.dev/`。

**认证（二选一，优先 A）**

- A. `npx wrangler login`：浏览器 OAuth 授权，令牌由 wrangler 本地保存，不写入仓库；如浏览器未自动打开，将输出的授权链接交给用户完成。
- B. 用户在终端临时设置 `CLOUDFLARE_API_TOKEN`（Pages:Edit 权限）与 `CLOUDFLARE_ACCOUNT_ID=2450b16d188a6686db33d4e1b31aff1a`，再执行部署。
- 不使用 `~/.wrangler` 之外的位置保存凭据；token 不写入任何文件或提交。

**部署命令**（在仓库根目录执行；wrangler 需要写入用户配置目录，必要时以非沙箱方式运行）

```
npx --yes wrangler@latest pages deploy docs/promo --project-name=starisle-promo --branch=main --commit-dirty=true
```

- Pages 单文件上限 25 MiB，三个 APK（12.5–12.9 MB）均满足；总文件数 5 个。
- 项目为 Direct Upload，部署后 `starisle-promo.pages.dev` 生效。

**失败处理**

1. 若 `starisle-promo` 返回项目不存在、被锁定或部署后仍 500：
   `npx --yes wrangler pages project create starisle-promo-v2 --production-branch=main`，再以新项目名重复部署。
2. 若 OAuth 无法完成（浏览器不可用 / 无网络）：跳过 Cloudflare 通道，保留 GitHub Pages 与插件通道，并在结果中说明所需授权。
3. 不使用 Cloudflare MCP 直接上传大文件（MCP 运行时无法读取本地文件，且站点 fetch 被拒 403），避免构造不完整产物。

**验证**：`Invoke-WebRequest https://starisle-promo.pages.dev/` 返回 200 且包含 `v2.3`、`15/15`；三个 `downloads/*.apk` HEAD 返回 200 且大小与本地一致。

### 4.4 Deployment 插件（备用分享链接）

按 `trae-remote-official:deployment` 的 StaticWeb 流程执行：

1. 准备临时源：`$env:TEMP\trae-deploy-<guid>\public\`，放入 `index.html`、`.nojekyll`、`downloads/*.apk`（5 个文件 / 约 40 MiB，满足 99 文件、50 MiB 限制）。
2. `sites list` → 无匹配站点则 `sites create --name "星屿 StarIsle 宣传页" --description "<仓库根 + docs/promo + 用途>" --access-policy public`。
3. `deployments create`（StaticWeb，`--title` / `--description` / 内容标签），随后 `deployments wait` 到终态。
4. 必要时 `sites refresh-screenshot`，最后调用一次 `show_deployment_card` 汇总成功站点。
5. 若 CLI 要求登录或无权限：停止插件通道，仅保留 GitHub Pages，并在结果中说明原因。
