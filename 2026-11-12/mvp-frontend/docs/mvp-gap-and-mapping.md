## 0. 一句话结论

ima 复刻版的信息架构（对话 / 发现 / 扩展清单 / 工具市场）与 StarIsle v2.2 的 MVP 定义**不重合**，因此本次不是换皮，而是**保留工程骨架、重写信息架构与页面**：保留零依赖零 CDN、自写 Markdown 渲染、`{ ok, state }` 状态回传、演示模式回退、响应式三形态与主题 token；把页面替换为学生端 / 教师端 / 家长端三套由**同一份构建、同一入口、同一数据层**驱动的角色视图。

## 1. 冲突裁决：Web 端到底有没有「AI 对话」

用户任务描述里把「AI 陪伴对话」列为学生端页面；README v2.2 第 13 行原文：

> Web 端进行去 AI 化重构——移除三端 AI 对话入口与页面，新增「知识库」（文章搜索 + 量表测评）与「树人互助」（求助社区）模块，与 App 端功能对齐；三端「我的」页新增「下载星屿 App」推荐卡片（含二维码）。AI 对话功能保留在 App（Flutter）端与微信小程序中。

裁决：**以 README 为准**。Web 端**不建** AI 对话页面、不留置灰入口、不做「敬请期待」假入口。取而代之：

| 原本想放的 AI 对话 | 本前端的实际落法 |
| --- | --- |
| 学生端 AI 星宝对话 | 学生端「知识库」（文章搜索 + 专业量表测评）+「树人互助」（发帖/回复）；「我的」页「下载星屿 App」卡片，说明对话在 App/小程序 |
| 家长端 AI 心理顾问「大星」 | 家长端「心理健康知识库」+「孩子情绪状态」；「我的」页下载 App 卡片 |
| 教师端 AI 对话观察 | 教师端「预警与干预」中保留**观察记录与干预记录**（人工协同），不出现 AI 对话窗口 |

这一条同时决定了三端「我的」页都必须有 App 下载卡片 —— 这是 README 明确要求的能力，不是补充设计。

## 3. ima 复刻版 → StarIsle MVP 概念映射

| ima 概念 | StarIsle 处理 | 说明 |
| --- | --- | --- |
| 首屏对话（Chat） | **删除** | 见第 1 节裁决 |
| 发现 / 探索流 | **删除** | 改为「知识库文章列表」+「树人互助帖子流」，两者是独立模块而非聚合推荐流 |
| 扩展清单（扩展/插件） | **删除** | StarIsle MVP 无插件/扩展概念，一个入口都不保留 |
| 工具市场 / 能力市场 | **删除** | AI 工具中心仅 App；Web 不出现 |
| 会话历史侧栏 | **删除** | 改为按角色固定的导航栏 |
| 附件 / 文件解析 | **删除** | MVP 无文档问答能力 |
| 分享卡片 | **保留形态，改写用途** | 仅用于「下载星屿 App」引导卡片 |
| 深色主题切换 | **保留** | 三端共用 |
| Markdown 渲染 | **保留** | 用于知识库文章正文、互助帖子正文 |
| 命令面板 / 快捷键 | **保留（简化）** | 桌面端 `Ctrl/⌘+K` 切换页面，角色内生效 |

## 4. 保留的工程资产（来自 ima 复刻版）

| 资产 | 处理 | 理由 |
| --- | --- | --- |
| 零依赖 / 零 CDN | **原样保留** | 硬性要求；`file://` 直开可用 |
| `assets/md.js` 自写 Markdown 渲染器 | **保留并改名** `window.SIMD` | 表格单元格单次 `inline()` 的修复、围栏未闭合兜底、`safeUrl()` 协议白名单都值得复用；仅替换 mermaid/markmap 的提示文案 |
| `{ ok, state }` 全量状态回传 | **保留** | 视图函数返回 `{ ok, state }`，由壳层决定 toast / 重渲染 |
| 演示模式回退 | **保留并强化** | 从「网络失败才回退」升级为**默认演示模式**，数据由 `assets/api.js` 的 mock 实现提供并持久化到 localStorage |
| 响应式三形态 | **保留** | 桌面多栏（≥1024）/ 平板 rail（768–1023）/ 手机底部 Tab（<768） |
| 主题 token | **替换取值** | 改用 `web-frontend/src/design/tokens.ts` 的 StarIsle 品牌色 |
| PWA（manifest / sw / icon） | **保留** | 可安装、可离线；改名称与主题色 |
| ima 的 CSS 类名体系 | **重写** | 原类名围绕对话流设计，无法承载三端角色导航；新 CSS 用 BEM 风格 + token 变量 |

## 5. 信息架构（改编后的实际结构）

单一入口 `index.html`，hash 路由，`role` 决定可用路由集合：

```
                     ┌──────────────┐
                     │  #/entry     │  角色选择 + 演示登录
                     └──────┬───────┘
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   role=student        role=teacher        role=parent
   ┌──────────┐        ┌──────────┐        ┌──────────┐
   │ #/student│        │#/teacher │        │ #/parent │
   └────┬─────┘        └────┬─────┘        └────┬─────┘
        │                   │                   │
   home 首页             home 工作台          home 孩子情绪
   knowledge 知识库      students 学生列表    children 绑定授权
   community 树人互助    alerts 预警与干预    emergency 应急预案
   relax 冥想放松        profile 我的         knowledge 知识库
   profile 我的                               profile 我的
```

全局层（三端共用，只渲染一次）：顶栏（品牌 + 角色切换 + 主题）、主导航、紧急帮助悬浮按钮、全屏应急面板、红色告警拦截层、Toast。

## 7. 已知取舍与遗留

1. **无真实后端**：默认演示模式；`assets/api.js` 内 `USE_MOCK` 是唯一切换点，后端就绪后只改该文件（详见 `api-contract.md`、`integration.md`）。
2. **知识库 / 树人互助未进 OpenAPI**：`web-frontend/src/services/api.ts` 已有调用，但 `api-docs/spec/openapi.yaml` 尚未收录，本前端按 `api.ts` 的定义固化契约并标注「待后端确认」。
3. **教师端「复核」闭环契约缺失**：`api.ts` 只有 `GET /v1/classroom/{classId}/alerts`，没有单条预警的复核/处置写入接口。本前端新增 `POST /v1/classroom/alerts/{alertId}/review`，在契约文档中标为**新增待确认**，mock 侧可完整演示。
4. **音频资源缺失**：冥想模块优先使用 `audioUrl`，无可用音频时降级为呼吸引导计时器，不出现空白播放器。
5. **二维码不做真实生成**：App 下载卡片使用内联 SVG 占位图案 + 文案，避免引入二维码库（零依赖约束）；真实二维码可在接入时替换为后端下发图片。
