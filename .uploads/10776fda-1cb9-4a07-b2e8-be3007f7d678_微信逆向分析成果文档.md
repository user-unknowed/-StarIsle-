## 一、分析结论总览

微信 4.x 已从旧版 `WeChat.exe` 单体程序演进为 **「轻量启动器 + 巨型核心业务 DLL」** 架构：

| 维度 | 结论 |
|---|---|
| 启动器 | `Weixin.exe`（3.0 MB），9 节区，仅静态导入 KERNEL32（176 函数），11 个延迟加载 DLL，**开启 CFG**，负责进程拉起与守护 |
| 核心库 | `Weixin.dll`（194.8 MB），12 节区，.text 段 119 MB，约 **51.4 万个函数**，117 个导出，39 个延迟加载 DLL / 898 个延迟导入函数，**未开启 CFG** |
| UI 框架 | **Qt**（存在 `.qtmetad` / `.qtmimed` 节区）+ **Skia** 2D + **ANGLE**（OpenGL ES → D3D11） |
| 网络栈 | **Chromium Cronet**（HTTP/2、QUIC、Brotli），另有腾讯自研 `gquic_*` 栈与 Winsock，三套并存 |
| 业务协议 | 腾讯 **Mars** 框架（长连接/CDN）+ **Protobuf**（micromsg / wmpf_host / finderlive 等协议族） |
| 跨进程 IPC | 自研 **mmmojo** 消息管道（22 个环境/读写/管道 API） |
| 音视频 | VoipEngine：**SILK 语音编解码**（微信经典语音格式）、Opus、WXAM 动图、AI 图片（AIGC） |
| 本地存储 | SQLite（`sqlite_master` 等符号）+ AES-128 加密（`aes_key` / `tp_aes_key` / `get_db_encrypt_info`） |
| 数据迁移 | roam_server：USB（Android Open Accessory）+ 网络双通道聊天记录备份迁移 |
| 小程序 | RadiumWMPF.bin（412.7 MB，ZIP 容器）独立小程序运行时 |
| 数字签名 | 两个主文件均为**有效的腾讯 Authenticode 签名** |

## 七、Ghidra 反编译结果

对 Weixin.exe 完成 Ghidra headless 全量自动分析（24 个分析器，总耗时 58 秒；主要：Stack 12.2s、x86 Constant Reference 11.1s、Disassemble Entry Points 6.9s、Decompiler Switch 6.2s），识别 **7,080 个函数**。

### 7.1 程序入口

```c
// entry @ 0x1401CCE00
void entry(void)
{
  __security_init_cookie();   // 栈保护 cookie 初始化
  __scrt_common_main_seh();   // MSVC CRT 标准主启动序列（SEH 包裹）
  return;
}
```

结论：标准 MSVC CRT 启动，无自定义入口混淆；随后由 CRT 调用 WinMain，再转入核心 DLL 的 `WeChatMain`。

### 7.2 唯一导出 GetHandleVerifier（Chromium Base 句柄校验器）

```c
// GetHandleVerifier @ 0x14004E8A0

{
  HMODULE hModule;
  FARPROC pFVar1;
  INT_PTR IVar2;
```

## 十一、安全观察

1. **CFG 不一致**：启动器 Weixin.exe 开启 Control Flow Guard，但 195 MB 的核心库 Weixin.dll 未开启（DllCharacteristics 0x0160，无 0x4000 位），核心库的 ROP/JOP 攻击面更大。
2. **自定义 CA 开关**：`SetUseUserCA` 导出与 `Cronet_EngineParams_verify_user_ca_set`、`enable_public_key_pinning_bypass_for_local_trust_anchors` 表明存在用户根证书/HPKP 旁路的程序化开关——利于企业审计与调试，也可能被滥用作中间人。
3. **反调试能力内建**：`CheckRemoteDebuggerPresent`、`DebugBreak`、线程上下文操作、dbghelp 自符号化、Crashpad 崩溃收集。
4. **可执行自定义节区**：Weixin.dll 的 `malloc_h` 节区带 X,R 属性，存在运行时代码生成/补丁能力，值得动态分析时重点关注。
5. **签名完整有效**：两主文件均通过 Windows Authenticode 链验证（腾讯 EV 证书），证书表各 10,800 字节。

## 十二、分析局限性

1. REA 的 Ghidra provider 因 Windows 提升令牌对象所有权问题（Win32 5）不可用，改用 Ghidra headless 直连；分析引擎相同，仅交互层不同。
2. Weixin.dll（195 MB）未做全量 Ghidra 反编译（预计需数小时）；函数总数 51.4 万为 `.pdata` 节容量推算（6,166,368 ÷ 12 B/RUNTIME_FUNCTION）。
3. 字符串证据为静态采样（每关键词组上限 10 条/关键词），非穷举；域名列表不代表完整端点集合。
4. 全程**静态分析**：未运行进程、未抓包、未 Hook，运行时行为（如自定义 CA 实际生效路径、malloc_h 用途）需后续动态验证。
5. 结论仅针对本机安装的 4.1.15.55 版本（构建时间 2026-10-12），不构成对腾讯通信协议的完整还原。
