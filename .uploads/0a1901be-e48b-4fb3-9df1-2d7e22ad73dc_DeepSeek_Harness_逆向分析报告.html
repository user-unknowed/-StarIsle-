DeepSeek Harness 桌面端逆向分析报告

目标版本：DeepSeek Harness v0.1.7-rc.2 (win-x64)

分析日期：2026-10-18

方法：PE 结构解析 + ASAR 解包 + 定向源码静态分析

1. 概述

DeepSeek Harness（dsh）是 DeepSeek 推出的桌面端 AI Agent 运行环境。本次逆向目标为官方 Windows x64 安装包 deepseek-harness-0.1.7-rc.2-win-x64.exe（288 MB），来源 https://download.deepseek.com/dsh-desk/bin/win-x64/。

核心结论：DeepSeek Harness 采用 Electron 外壳 + dsh Cordis 插件运行时 架构。Electron 主进程只负责窗口、托盘、自动更新、IPC 与 WebSocket 流式协议；所有业务能力（LLM、工具、沙箱、会话、账户、搜索等）均以 273 个 @deepseek-ai/dsh-* 插件 的形式通过 Cordis 内核动态加载。安装包捆绑了完整的 Node.js 24.18.1 + Python 3.12 + pnpm 11.7.0 运行时。

6. 关键子系统逆向

6.1 LLM 接入层（dsh-llm-deepseek）

端点https://api.deepseek.com/anthropic（env: DEEPSEEK_BASE_URL）
协议Anthropic Messages API（anthropic-version: 2023-06-01）
模型deepseek-flash (V41-Flash, text+image)、deepseek-v4-pro
上下文1,000,000 tokens
最大输出256,000 tokens
推理强度off / low / high / max（默认 high）

Files API：{base}/v1/files，单文件 ≤128 MiB，存储配额 25 GB / 10,000 文件，过期 1h~30d（默认 7d）。

上传索引：$DSH_HOME/llm-deepseek/files-v3.json，命名空间 = SHA-256(baseURL + 认证头)，不持久化明文密钥。

视觉计费：14px patch、3:1 下采样、单图 ≤1024 tokens；≥15 图时单边 ≤4096px；单请求 ≤600 图。

6.2 联网搜索（dsh-web-search-deepseek）

端点https://api.deepseek.com/anthropic/v1（env: DEEPSEEK_SEARCH_BASE_URL）
模型deepseek-v4-flash，max_tokens 4096
工具web_search_20250305，max_uses 默认 5
API KeyDEEPSEEK_API_KEY
User-Agentdeepseek-harness/0.0.1

同时发送 x-api-key 与 authorization: Bearer 头。响应从 web_search_tool_result 块提取结果并按 URL 去重。

6.3 账户与认证

端点用途
/auth-api/v0/dsh/<method>DSH 平台方法
/auth-api/v0/users/current当前用户
/auth-api/v0/users/logout登出
/api/v0/users/get_unnotified_bonuses未读奖励
/api/v0/users/ack_bonus_notified确认奖励

认证头：x-dsh-auth-token: <token>。HTTP 401 或 code: 40003 触发重新登录。登录经浏览器 loopback 回调。含平台奖励/钱包体系。

6.4 会话持久化（dsh-session-persistence-jsonl）

格式：JSONL，支持 Zstandard 压缩（.jsonl.zstd）。

路径：<root>/<project key>/<encoded session id>/session.v<N>.jsonl[.zstd]

  • project key 由 cwd 派生（分隔符→-，包裹 --...--）
  • session id 用 ~XXXX 转义防路径穿越
  • 当前格式版本 v4，内置 v0→v4 迁移链

跨进程写锁：Windows 用命名内核信号量 Local\dsh-session-lock-<sha256>；POSIX 用 flock。进程崩溃由内核自动释放，无超时。

Windows 持久化：MoveFileExW(..., MOVEFILE_WRITE_THROUGH) 实现写入穿透。

6.5 沙箱策略（dsh-sandbox-policy）

模式行为
read-only（默认）禁止任何文件修改
workspace-write仅允许修改会话工作目录
danger-full-access不限制文件修改

解析优先级：显式批准 > 会话 sandbox/mode 事件 > 部署默认。工作区根 = 会话 cwd。

6.6 凭据管理（dsh-credentials）

  • CredentialRef：环境变量名（如 DEEPSEEK_API_KEY），层级 = 进程环境 → 提供者存储 → .env
  • CredentialKey：<scope>/<id> 格式，modifyRecord 为唯一写入路径（读-决-替，加锁）
  • 空值视为未配置；变更通过事件通知，监听器失败被隔离

6.7 家目录与匿名标识

  • DSH Home：默认 ~/.dsh，env DSH_HOME 可覆盖
  • 匿名用户 ID：$DSH_HOME/.anonymous-user-id，crypto.randomUUID() 生成，不派生自主机名/MAC/git remote
  • 用途：遥测与反馈；删除文件后下次启动生成新 ID

6.8 Electron 主进程（lib/main.js）

IPC 通道：DESKTOP_IPC（boot, shortcuts, updates, locale...）、WELCOME_IPC（saveApiKey, start...）、MANDATORY_IPC、UPDATE_DIALOG_IPC、PLATFORM_IPC。

流式协议：ws 连接 ${origin}${REMOTE_STREAM_MUX_PATH}，来自 @deepseek-ai/dsh-api-gateway/stream-protocol。

自动更新：electron-updater，源 https://harness.deepseek.com，anonymous 认证。

捆绑运行时：Node → resources/runtime/bin，pnpm → resources/runtime/pnpm/bin/pnpm.mjs。

8. 安全与隐私观察

设计良好的方面

  • 沙箱默认 read-only，Agent 无法擅自改文件
  • 配置只存环境变量名，不存密钥值
  • 上传索引用哈希派生命名空间，不持久化明文密钥
  • 匿名 UUID 与机器标识解耦
  • 会话写锁崩溃自动释放、无超时，防止撕裂
  • Windows MOVEFILE_WRITE_THROUGH 确保持久性
  • HTTP 请求 redirect: "error"，防止凭据被重定向带出

需要关注的方面

  • 存在 danger-full-access 完全关闭沙箱的模式
  • x-dsh-auth-token 为长期凭据，泄露风险需关注
  • 会话日志明文存储于 ~/.dsh（zstd 压缩非加密）
  • 自动更新 anonymous 认证，依赖 HTTPS + 代码签名

10. 分析局限性

  1. REA 全量分析产出 222 MB JSON 超出内存，改为定向读取关键插件，未覆盖全部 273 个插件。
  2. 未做动态抓包，端点均来自源码静态提取，运行时可能存在动态构造的 URL。
  3. app.asar.unpacked/ 下原生 Node 模块未做 Ghidra 分析。
  4. 渲染层与 dsh-client-ui-* 前端逻辑未深入。
  5. 凭据具体持久化实现（是否加密）未追踪到底。

本报告基于静态逆向分析，仅供技术研究与架构理解之用。
