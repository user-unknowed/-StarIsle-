# StarIsle 三端前端工具设计与部署计划

## 概述

为 StarIsle 青少年心理健康 AI 应用设计并部署「三端前端工具」，交付两套独立部署的 Web 应用：

1. **统一 API 调试工具**（扩展现有 `api-docs/`）：按学生/教师/家长三端分组展示应用内**全部** API 接口，逐个接口提供输入参数表单与输出响应展示面板。
2. **三端真实业务前端**（扩展现有 `web-frontend/`）：补齐缺失的家长端，三端均接入真实 API，并在业务界面中展示 API 输入输出结果。

两套应用均通过 **IGA Pages** 静态部署上线。使用 `trae-remote-official:frontend-design` 与 `trae-remote-official:web-app-development:uicraft` 技能指导 UI 设计与实现。

## 假设与决策

1. **两套应用独立部署**：api-docs 与 web-frontend 分别构建为静态站点，各自部署到 IGA Pages（两个独立 URL）。
2. **不引入新重型依赖**：API 调试工具沿用 `@scalar/api-reference-react` + 自研三端导航面板；业务前端沿用现有栈，HTTP 用原生 fetch（已有 `services/http.ts`）。
3. **OpenAPI 规范补全**：扩展 api-docs 前，先补全 `openapi.yaml` 中缺失的 Risk/Content/Assessment/Migration-Key/User-Export 端点，确保「连接所有 API」名副其实。
4. **业务前端输入输出展示**：三端业务页面接入真实 API 后，用户输入（如发消息/打卡/绑定孩子）→ 界面实时展示 API 返回结果（输出）；另加一个轻量「API 调试浮层」开关，可查看最近请求/响应明细，明确满足「显示输入输出结果」要求。
5. **CORS 与降级**：浏览器直连后端受 CORS 限制，API 调试工具与业务前端均保留「后端不可用时提示/降级」策略；生产环境通过 IGA Pages 反代或后端开启 CORS（已有 `CorsConfig.java`）。
6. **Electron 不参与 Web 部署**：api-docs 的 Electron 入口仅在桌面打包时使用，Web 部署只用 `vite build` 产物。
7. **设计风格统一**：两套应用沿用 StarIsle 品牌色（#6B7BFF/#A78BFA 渐变）与圆角卡片风格，家长端用暖色点缀以区分。

## 风险与降级

- **CORS**：浏览器直连 `localhost:8080` 后端受 CORS 限制，`CorsConfig.java` 已配置允许；部署后若跨域，由后端配置或 IGA Pages 反代解决。前端在请求失败时显示明确错误，不阻塞 UI。
- **后端未启动**：业务前端 Store 保留 mock 降级；API 调试工具显示请求失败状态码 0 与错误信息。
- **OpenAPI 规范与实际后端偏差**：以 Java Controller 注解为真相源补全规范；规范与实现不一致时以后端为准并记录。
- **IGA Pages SPA 路由**：改用 HashRouter 规避服务端回退缺失。
