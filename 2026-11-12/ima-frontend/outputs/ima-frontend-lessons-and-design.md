## 第一部分 · 经验教训

### 1.1 原版不是"一个网页"，所以不能照抄它的前端

逆向结论里最有约束力的一条：ima.copilot 是**定制 Chromium 150 外壳**（不是 Electron，没有 asar 可解），界面由 `chrome://home/` 原生壳页 + **24 个 MV3 扩展**共同构成，`chrome_url_overrides` 把 `allknowledge` / `note` / `history` / `global_settings` 四个页面直接接管，还注册了专有权限 `imaFrame`。

这决定了三件事：

1. **它的"页面"其实是扩展页**，路由、权限、跨页通信都建立在 `chrome.*` 之上。我们没有任何 `chrome.*` 可用（浏览器里没有，Swing 里也没有）。
2. **能力上限由外壳给**：本地文件解析、PDF/Office/EPUB 渲染、录音、播客都跑在独立扩展里，靠专有权限访问文件系统。纯 Web 沙箱拿不到这些，所以只能占位。
3. **可以照抄的是"信息架构和视觉"，不是"实现方式"**。所以新前端的第一原则是：**用一套自绘的、单页的、零依赖的实现，去逼近那套多扩展拼出来的产品的观感与操作路径**。

### 1.2 原版技术栈事实与可迁移性

| 原版事实 | 出处 | 对本项目的结论 |
| --- | --- | --- |
| React + TDesign React | 报告 §9 | 组件形态（卡片、胶囊按钮、开关、细线分割）值得抄；运行时不必抄。复刻工程是零依赖约束，引入 React 等于把构建链和体积问题一起引进来 |
| markdown-it 渲染 | 报告 §9 / 扩展清单里的 markdown 5.14.3 | 渲染规则要抄（表格、代码块、引用、链接），实现必须自己写 |
| KaTeX / markmap / mermaid / cytoscape | 报告 §9 | 数学公式、脑图、流程图、关系图**全部占位**。它们不是"一段正则"，而是完整的排版/布局引擎，零依赖前提下无法在不引入第三方库的情况下复刻 |
| html2canvas | 报告 §9 | 导出图片能力占位（截图分享在浏览器里不是刚需） |
| MV3 扩展清单 24 项 | 报告 §11 | 「发现」页的原型：把 24 项连同扩展 ID、版本、复刻状态一起列出来。这是唯一能诚实表达"我们做到了哪一步"的界面 |
| Shiply 增量更新、Beacon/Bugly/QIMEI/ImSDK 遥测 | 报告 §1 | 一律不复刻。本地复刻版没有服务端，做遥测既无意义也不合适 |

### 1.3 为什么这些能力只能占位（而不是"以后再做"）

判断标准不是"难不难"，而是**缺的是代码还是缺的是宿主能力**：

| 能力 | 占位原因 | 占位形态 |
| --- | --- | --- |
| 云端大模型问答 | 复刻版没有模型服务，`AiEngine` 是本地规则引擎 | 正常对话，但回答由本地引擎生成，界面上标注"本地引擎" |
| 全网搜索 / 联网摘要 | 没有搜索后端，且会引入网络依赖（违背离线可用） | 「发现」页标注占位，不提供入口 |
| 多端同步 / 登录 | 没有账号体系 | 设置页不出现登录项，避免假按钮 |
| PDF / Office / EPUB 阅读 | 需要 PDFium / Office 渲染栈；Web 端不引第三方库做不到 | 上传时明确提示"仅支持纯文本类文件"，不假装能解析 |
| 音视频、录音、TTS、播客 | 需要媒体管线与云端语音服务 | 「发现」页标注占位 |
| 脑图 / 流程图 / 公式 | 需要 markmap / mermaid / KaTeX 级别的引擎 | Markdown 中遇到时**降级为可读文本**，不报错、不白块 |
| 扩展安装与 `chrome.*` 权限 | 浏览器 / Swing 都没有扩展宿主 | 「发现」页只做静态清单展示 |

写进设计里的规矩：**占位要看得见、说得清**。宁可显式写"占位"，也不要做一个点了没反应的按钮——后者比缺失更伤信任。

### 1.4 复刻工程已经踩过的坑（新前端必须绕开）

| 坑 | 现象 | 对新前端的处置 |
| --- | --- | --- |
| 零第三方依赖 | README 明确约束；`build.gradle.kts` 只有 kotlin-stdlib | 前端同样零依赖、零 CDN、零构建：只有 `.html/.css/.js`，双击可开 |
| Gradle wrapper / JDK 固定 | Gradle 8.9 + JDK 17 + Kotlin 1.9.25，换版本就炸 | 前端不碰构建链；静态文件做成"拷进去就能用"，不需要重新编译 |
| exFAT 盘构建失败 | `G:` 为 exFAT，Gradle 清理 `build` 目录时报 "not empty"，需改名 `build-old` 绕过 | 前端产物不做任何磁盘级操作；复制交付时用整目录拷贝而非增量同步 |
| 125% DPI 截图偏差 | Robot 截图边缘混入桌面/任务栏 | 验证改走真实浏览器 + 静态服务，不再依赖 Swing 截图 |
| **Markdown 表格单元格内联样式未二次解析** | 表格里写 `**粗体**` 显示为字面量 | 见 2.7：行内解析只对**原始文本**做一次，表格单元格直接把原始 cell 交给行内解析器 |
| Room / 数据库依赖 | 移动端只能用 `com.sun.net.httpserver` + 文件 JSON，没有数据库 | 前端只认 `/api` 的 JSON，不假设任何持久化细节 |
| 数据目录权限 | `~/.ima-clone` 在受限环境下不可写 | 前端必须有**演示数据回退**，服务端起不来也能完整展示 |
| 静态资源根固定 | `MobileServer` 只从 classpath `/mobile/` 取文件 | 新前端独立目录，接入方式写成方案（第三部分），不改 Kotlin |

### 1.5 上一版移动端 PWA 的得与失

**可复用的（已经验证有效的）**

- **`{ ok, state }` 全量回传**：所有修改类接口都返回最新全量状态，前端只做"覆盖 state → 重渲染"。这套模型让前端不需要维护增量补丁逻辑，服务端也不需要事件推送，是本地单用户场景下的最优解。新版继续沿用，并把它抽象成唯一的写入通道。
- **断点分层**：`<760px` 底部 Tab、`≥760px` 78px 图标 rail、`≥900px` 会话侧栏常驻、`≥1100px` rail 展开。这套分层符合真实设备宽度，新版沿用并补上"桌面三栏"。
- **安全区与视口**：`viewport-fit=cover` + `env(safe-area-inset-*)` + `100dvh`，在 iOS Safari 上不跳动、不被刘海遮挡。
- **主题通过服务端保存**（`state.dark`），多端一致；`meta[name=theme-color]` 随主题变化。
- **文件编码兜底**：`TextDecoder('utf-8', {fatal:true})` 失败后回落 `gb18030`，中文 TXT 不乱码。
- **Service Worker 只缓存静态壳，`/api/` 永远走网络**：避免读到过期数据。

**不足（新版逐条修）**

| 不足 | 后果 | 新版做法 |
| --- | --- | --- |
| 没有桌面三栏 | 宽屏下右侧大片空白，会话列表挤在 292px 里 | 桌面 = rail + 会话列 + 对话区；笔记 = 列表 + 编辑 + 预览 |
| `/api` 不可达即白屏/空态 | 直接双击 `index.html` 只能看到错误 | 内置演示数据集，探测失败自动进入「演示模式」，界面完整可点 |
| 表格单元格内联样式丢失 | 见 1.4 | 重写 Markdown 渲染器 |
| `messages` 全量 `innerHTML` 重绘 | 长会话滚动位置跳动、输入法候选被打断 | 增量追加节点 + 仅在状态整体替换时重绘，发送流程用乐观气泡 + 占位气泡替换 |
| 无键盘体系 | 桌面上效率低 | `Alt+1..5` 切页、`Ctrl/⌘+K` 新建会话、`Esc` 关抽屉、`/` 聚焦检索、`Ctrl+Enter` 发送 |
| 无 `aria-*` / 焦点管理 | 屏幕阅读器读到的是散装 div | `role="log"`、`aria-live`、抽屉焦点陷阱、可见焦点环 |
| 会话删除无确认 | 误删不可恢复 | 二次确认（内联确认条，不用 `confirm()`） |
| 没有"检索中"的语义 | 只是三个点 | 明确的阶段文案 + `aria-busy` |

## 第二部分 · 设计方案

### 2.1 三条取舍原则

1. **形态优先于功能**：先把"三栏 / rail / 底部 Tab"三种形态和走路路径做对，再谈功能。原版给人的第一印象是"轻、绿、密"，这比多一个按钮重要。
2. **诚实的降级优于假装支持**：不支持的能力在界面上以"占位"出现，不制造死链。
3. **单一数据源**：任何写入都以服务端返回的 `state` 为准；本地只保留三类临时态（乐观消息、防抖中的笔记草稿、演示模式下的本地状态）。绝不出现"前端自己算了一份、服务端算了一份"。

### 2.2 信息架构

五个一级页面，和原版的扩展覆盖页一一对应：

| 页面 | 对应原版 | 核心任务 | 关键动作 |
| --- | --- | --- | --- |
| 对话 | 问问ima + 首页 | 带着本地资料提问 | 新建/切换/删除会话、发送、查看引用命中 |
| 知识库 | IMA知识库 | 把资料变成可检索的片段 | 导入、删除、清空、检索测试 |
| 笔记 | 记笔记 | 写 Markdown 并即时看到排版 | 新建、编辑、实时预览、防抖保存、删除 |
| 发现 | 24 个扩展 | 交代"复刻到哪一步" | 按状态筛选、看扩展 ID 与版本 |
| 设置 | IMA设置 | 主题、运行信息、数据重置 | 切主题、安装 PWA、重置 |

导航层级只有一层。原版用扩展把功能切成"应用"，复刻版没有扩展宿主，**用一级导航 + 页内分栏**替代，减少跳转层级。

### 2.3 布局与响应式降级

四个断点，对应四种真实使用场景（而不是"为了响应式而响应式"）：

| 宽度 | 形态 | 布局 | 为什么这样降 |
| --- | --- | --- | --- |
| `≥1180px` | 桌面宽屏 | rail 展开 216px + 会话列 288px + 对话区自适应；笔记为 列表+编辑+预览 三列 | 宽屏的信息密度足够，三栏能让"切换会话"和"读内容"同时成立 |
| `900–1180px` | 桌面窄 / 横屏平板 | rail 收成 72px 图标 + 会话列 264px + 对话区 | 侧栏展开会挤压正文；图标 rail 保留一级导航的可达性 |
| `760–900px` | 竖屏平板 | rail 72px，会话列改为**覆盖式抽屉** | 三列会让正文窄到 380px 以下，阅读体验崩塌；抽屉保住了"随时切会话" |
| `<760px` | 手机 | 顶部栏 + 内容 + 底部 Tab，会话抽屉覆盖全高 | 拇指可达区在底部；顶部只留标题与一个抽屉按钮 |

实现要点：

- 高度用 `height: 100dvh`（回退 `100vh`），配合 `overflow:hidden` 的外壳，只有内容区滚动。这样移动端地址栏收放不会把输入框顶出屏幕。
- 安全区：顶栏 `padding-top: calc(10px + env(safe-area-inset-top))`，底部 Tab `padding-bottom: env(safe-area-inset-bottom)`，输入框容器同样避让。这样刘海屏和手势条不遮挡。
- 抽屉：`transform: translateX(-102%)` + `scrim` 淡入淡出，`Esc` / 点遮罩关闭，打开时焦点移入抽屉并在内部循环。
- 不使用 CSS 容器查询（兼容性收益不抵复杂度），断点全部走 `@media`。

### 2.4 设计语言

延续 Swing 端与旧 PWA 的基线：**近黑底 + 品牌绿 + 低对比分割线 + 大圆角**。绿色是唯一强调色，只用于"主操作 / 选中 / 命中"，不用于装饰。

**色彩 token（`assets/app.css` 顶部，CSS 变量）**

| Token | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#101011` | `#f5f7f8` | 应用底色 |
| `--panel` | `#181819` | `#ffffff` | 卡片、侧栏 |
| `--panel-2` | `#202022` | `#eef1f3` | 输入框、次级块 |
| `--line` | `#2a2a2c` | `#e3e6e9` | 1px 分割线 |
| `--text` | `#ececed` | `#1a1c1e` | 主文本 |
| `--dim` | `#8d8d92` | `#697077` | 次要文本 |
| `--brand` | `#079d55` | `#079d55` | 品牌绿（固定，不随主题变） |
| `--brand-soft` | `rgba(7,157,85,.16)` | `rgba(7,157,85,.12)` | 选中底 |
| `--bubble` | `#202022` | `#eef1f3` | 助手气泡 |
| `--user-bubble` | `#0b5c39` | `#d8f6e7` | 用户气泡 |
| `--danger` | `#e5484d` | `#cf2f35` | 危险操作 |

**其他基线**

- 圆角：卡片 16px、按钮 10–11px、气泡 16px（靠内侧一角收成 6px，形成方向感）、输入框 14px。
- 字体：系统栈（`-apple-system` / `PingFang SC` / `Microsoft YaHei`），正文 14–15px，行高 1.6；代码用 `ui-monospace`。
- 滚动条：8px、圆头、`--line` 色，hover 变 `--dim`；不使用完全隐藏（桌面需要可见的滚动提示）。
- 动效：只做 120–220ms 的位移/透明度；`prefers-reduced-motion` 下全部关闭。
- 阴影极克制：只有浮层（抽屉、toast、下拉）用阴影，平面内容用 1px 描边分层。

### 2.5 页面与交互细节

**对话**

- 会话列：标题 + 相对时间 + 最后一条消息预览；hover 出现删除按钮，删除走内联二次确认（该行变成"删除？确认 / 取消"），不用系统弹窗。
- 消息流：助手消息左侧 `ima` 头像，用户消息右侧；气泡内 Markdown 渲染。
- 发送：先插入用户气泡 + 一个 `aria-busy` 的"正在检索本地知识库…"占位气泡，接口返回后用真实回答替换占位。失败则把占位替换成错误气泡，并**保留**用户消息（服务端已存），状态以返回的 `state` 为准。
- 输入框：`Enter` 发送、`Shift+Enter` 换行、`Ctrl/⌘+Enter` 也发送；高度随内容增长到 5 行封顶；发送中禁用按钮但不禁用输入。
- 空态：一句引导 + 两个快捷入口（去知识库导入、看示例问题）。

**知识库**

- 顶部统计：文档数 / 片段数 / 总字数，来自 `state.kb`。
- 文档列表：文件名 + `字数 · 时间`，右侧删除。
- 导入：`input[type=file][multiple]`，逐个读取 → 编码兜底（UTF-8 → GB18030）→ `POST /api/kb/upload?name=`；逐个提示结果，`ok:false` 时显示服务端给的 `message`（例如超限）。
- 清空：危险操作，二次确认条。
- 检索：输入回车触发 `GET /api/kb/search?q=`，命中卡片显示文档名、片段序号、分数与高亮片段；空结果显示"没有命中"。

**笔记**

- 左列笔记列表（标题 + 预览 + 时间）。
- 编辑器：标题输入 + 正文 `textarea`（等宽字体，`Tab` 插入两个空格而不是跳焦点）。
- 预览：三态切换「编辑 / 分栏 / 预览」。`≥1180px` 默认分栏，窄屏默认编辑。
- 保存：输入后 **700ms 防抖**自动保存；切换笔记/切页/`beforeunload` 前强制 flush；工具栏显示"未保存 / 保存中 / 已保存"。
- 删除：二次确认。

**发现**

- 24 个模块卡片：名称、版本、扩展 ID（等宽小字）、状态徽章、一句说明。
- 顶部筛选：全部 / 已实装 / 部分实装 / 占位，附各状态计数。
- 数据来自 `GET /api/catalog`；演示模式下用内置清单。

**设置**

- 外观：深色主题开关（立即改 `data-theme`，同时 `POST /api/settings`）。
- 运行信息：引擎、数据目录、会话/笔记数、知识库片段数、当前端、版本。
- 安装：`beforeinstallprompt` 捕获后显示按钮；不支持时给出手动添加的说明。
- 重置：危险区，二次确认后 `POST /api/reset`。

### 2.6 状态管理与 API 对接

**单一状态对象**，结构严格等于 `stateJson()`：

```
{ app, version, engine, dark, dataDir, currentSessionId,
  sessions: [{ id, title, updatedAt, time, count, preview }],
  notes:    [{ id, title, updatedAt, time, preview, content }],
  kb:       { chunks, chars, docs: [{ id, name, chars, time }] } }
```

外加三个界面态（不进 state）：`view`（当前页）、`session`（当前会话详情，含 messages）、`catalog`。

**写入通道只有一个**：

```js
async function mutate(path, body) {
  const r = await post(path, body);
  applyState(r.state);      // 全量覆盖
  return r;
}
```

`/api/chat` 例外，额外带 `session`：用它替换 `session`，再用 `state` 覆盖列表。

**API 基址探测**（因为同一套文件要同时支持三种打开方式）：

1. `file://` → 直接演示模式（`fetch` 对 `/api` 无意义）。
2. 否则依次尝试 `/api`、`./api`、`../api` 的 `GET /api/state`，1.2s 超时，第一个返回合法 `state` 的作为基址。
3. 全失败 → 演示模式。

**演示模式**：内置一份与真实结构完全一致的数据（含一段带表格/代码/引用的会话、两篇笔记、两份知识库文档、24 条模块清单），并实现一个**本地 reducer** 复刻服务端语义（新建/选中/删除会话、按 kb 片段做简单检索生成回答、笔记 CRUD、导入切片、检索打分、重置）。所有调用走同一套 `mutate()`，只是后端换成本地函数。这样"能演示"和"能联调"用的是同一条代码路径，不会出现两套 UI 逻辑。

**错误处理**：网络错误 / 非 JSON / `ok:false` 统一抛错，由调用方 `toast` 提示；不做全局错误页，局部失败不影响其他区域。

### 2.7 Markdown 渲染（自实现，无依赖）

处理顺序（这是修复旧缺陷的关键）：

1. **先抽代码块**：```` ```lang ... ``` ```` 整块抽成占位符，内容只做 HTML 转义，**不再进入任何行内解析**。
2. **逐块识别**：标题、分隔线、引用、表格、有序/无序列表、段落。
3. **表格**：把**原始**单元格文本直接交给行内解析器 —— 行内解析器内部只做一次"转义 → 保护行内代码 → 链接 → 强调 → 还原代码"。旧版在这里对已转义文本二次解析，导致 `**粗体**` 不生效；新版保证"一份文本只解析一次"。
4. **行内**：`` `code` `` 先抽占位 → 图片降级为 `[图片 alt]` → `[text](url)` 转 `<a rel="noopener noreferrer" target="_blank">` → `**粗**`/`__粗__`/`*斜*`/`~~删除~~` → 还原行内代码。
5. **降级策略**：原始 HTML 标签全部转义（不执行）；`$公式$`、`[[双链]]`、mermaid 代码块按普通文本/普通代码块显示，不报错。

### 2.8 可访问性与键盘

- 语义：`nav` / `main` / `aside` / `section` + 每页一个 `h1`；消息流 `role="log" aria-live="polite" aria-relevant="additions"`；toast `role="status"`。
- 焦点：所有可交互元素有可见焦点环（`:focus-visible`，2px 品牌绿）；抽屉打开时焦点进入并在内部循环，关闭后回到触发按钮；跳过导航链接。
- 键盘：`Alt+1..5` 切页、`Ctrl/⌘+K` 新建会话、`/` 聚焦当前页检索框、`Esc` 关闭抽屉/取消确认、`Ctrl+Enter` 发送。
- 对比度：正文与底色 ≥ 7:1，`--dim` 与底色 ≥ 4.5:1；状态不只靠颜色（徽章带文字）。
- `prefers-reduced-motion` 关闭动画；`prefers-color-scheme` 仅作为首次进入的默认值，之后以服务端 `dark` 为准。

### 2.9 明确占位的能力

对话的**云端模型**、**全网搜索**、**多端同步/登录**；知识库的 **PDF / Office / EPUB / 音视频解析**（只接受纯文本类文件）；笔记的**脑图 / 流程图 / 公式 / 导出图片**；「发现」页中除对话、知识库、笔记之外的所有模块（搜索、收藏、历史、翻译、PDF、office、epub、播客、音频、录音、图片工具、code、HTML 沙箱、copilot、qo_documents、用量统计等）。占位在「发现」页有明确徽章与说明，在具体页面不生成假入口。

## 第三部分 · 接入说明（如何挂到现有 HttpServer）

新前端是纯静态目录，不改任何 Kotlin 代码即可**独立运行**（任意静态服务器 / 直接双击 `index.html` 走演示模式）。若要让它取代旧 `mobile/`，有三种改法，按侵入性从小到大：

**方案 A（推荐，零改 Kotlin）** 把 `frontend/` 下的文件整体拷进 `app/src/main/resources/mobile/`，覆盖同名文件（`index.html`、`app.css`、`app.js`、`manifest.webmanifest`、`sw.js`、`icon.svg`）。新前端的资源引用全部是相对路径，API 走绝对 `/api` 探测，落位后与旧版行为一致，无需动 `MobileServer.kt`。

**方案 B（并存，改 3 行）** 在 `MobileServer.static()` 里增加一个前缀分支：`/v2/` 映射到 classpath `/frontend/`，其余仍走 `/mobile/`。资源放 `app/src/main/resources/frontend/`。这样旧版可回退。

**方案 C（独立目录）** 把 `frontend/` 作为 Gradle `processResources` 的额外资源目录（`sourceSets["main"].resources.srcDir("../frontend")`），再由 `static()` 把 `/` 直接指向它。

无论哪种方案，`/api` 契约都不需要变：新前端只用到 README §3.3 列出的那些端点，字段名严格对齐 `stateJson()` / `sessionJson()`。

**与旧 mobile 版的关系**：新版是超集——同样的五个页面、同样的 `{ ok, state }` 全量回传、同样的断点基线；新增桌面三栏、预览分栏、演示数据回退、键盘体系、Markdown 修复。旧版可以保留作为回退路径，也可以被方案 A 直接覆盖。

**未完成 / 占位**：见 2.9；另有两点工程限制——(1) 演示模式下的回答由本地规则生成，不代表真实模型效果；(2) 未验证在真机 iOS/Android 上的安全区表现（仅按标准 `env()` 写法实现，桌面 Chromium 与移动模拟下验证）。
